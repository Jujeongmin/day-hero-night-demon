# 시작 흐름(컷신·닉네임·튜토리얼)과 설정 — 설계 (2026-09-29)

## 목표

게임을 처음 켠 사람이 뜬금없이 탑 화면에 떨어지지 않게 한다. 짧은 스토리 컷신 → 닉네임 정하기 → 클릭만 하면 진행되는 튜토리얼 순서로 핵심 루프(공략·배치·강화·매칭)를 한 바퀴 돌게 한다. 설정 화면(소리·닉네임·데이터 초기화)을 만든다.

성공 기준
- 새 계정은 컷신 → 닉네임 → 튜토리얼을 **계정당 한 번만** 본다. 다른 기기·새로고침에서도 다시 뜨지 않는다(서버 저장).
- 튜토리얼 중 화면 아무 데나 눌러도 다음으로 진행되고, 실패할 수 없다.
- 기존 계정(이미 입문 공략을 끝낸 계정)은 아무것도 보지 않는다. 닉네임만 한 번 정하게 한다(아래).
- 모바일 세로 360×640 ~ 414×896에서 넘침·겹침 없음.

## 1. 흐름

```
접속 → 서버 상태 확인
  onboarding.step = 'cutscene'  → 컷신 5장 (건너뛰기 가능)
  onboarding.step = 'nickname'  → 닉네임 입력
  onboarding.step = 'tutorial'  → 튜토리얼 (tutorial 하위 단계)
  onboarding.step = 'done'      → 평소 화면
```

### 컷신 (5장, 이미지 240×240 + 아래 대사창)
1. 텅 빈 금고. 임프 집사: "마왕님, 성 유지비가 석 달째 밀렸습니다."
2. 임프: "옆 동네 마왕성들은 금이 넘친답니다… 용사들이 매일 털어 가서 문제지요."
3. 마왕 눈이 빛남: "…그럼 나도 용사가 되면 되겠군."
4. 부하들을 기사·궁수·성직자로 꾸민 '용사 파티': "낮엔 용사로 남의 성을 털고,"
5. 붉은 달 아래 탑 꼭대기의 마왕: "밤엔 마왕으로 내 성을 지킨다." → 제목 로고 "낮엔 용사, 밤엔 마왕"

- 화면 아무 데나 누르면 다음 장. 오른쪽 위 "건너뛰기". 마지막 장 다음 닉네임 화면.
- 그림은 PixelLab `create_image_pixflux` 240×240, 컷마다 후보 2장(약 10회). **후보 승인 후 반영.** 마왕은 괴물형(`art-style.md`), 임프는 게임 속 임프와 같은 모습.
- 대사창·로고 글자는 기존 UI 키트(`frame_sq`)와 Do Hyeon 글꼴.

### 닉네임
- 2~8자, 한글·영문·숫자만(공백·기호 불가). 서버가 검사한다.
- **중복 불가.** 서버가 Global Collection `nicknames`(id = 소문자로 바꾼 닉네임, 값 = account)로 확인·등록한다. 같은 계정 락 안에서 확인 → 등록.
- 금지어 목록(욕설·운영자 사칭 "운영자", "관리자", "GM", "verse8" 등)은 `server/src/nickname.ts`에 둔다.
- 기존 계정: 지금은 `마왕 #ABCD` 자동 이름이다. `onboarding.nicknameSet = false`이면 다음 접속 때 닉네임 화면만 한 번 뜬다(컷신·튜토리얼 없음).
- 변경: 설정에서 **1회 무료**. 그 뒤로는 막는다(나중에 유료 변경권을 붙일 수 있게 `profile.nicknameChanges` 카운트만 둔다). 바꾸면 옛 이름을 `nicknames`에서 지우고, `castles` 컬렉션과 이번 시즌 리그 항목의 닉네임도 갱신한다.

### 튜토리얼 (한 바퀴, 방치 수입 단계 없음)
위쪽에 임프 초상화 + 말풍선 한 줄. 눌러야 할 것 하나만 빛나고 나머지는 어둡게 막힌다. **화면 어디를 눌러도 빛나는 대상이 눌린 것처럼 진행.**

| 하위 단계 | 빛나는 대상 | 임프 대사(초안) | 넘어가는 조건 |
| --- | --- | --- | --- |
| raid_sortie | 출정 버튼 | "우선 옆 동네 길드 성부터 털어 봅시다!" | 입문 공략 시작 |
| raid_tactic | 전술 버튼(첫 번째) | "전술을 고르시면 알아서 싸웁니다." | 전투 재생 시작 |
| raid_ult | 궁극기 버튼 | "지금입니다! 궁극기!" | 궁극기 사용(준비되면) |
| raid_result | 결과창 확인 | "금화가 들어왔습니다!" | 결과창 닫힘 |
| place_floor | 1층 | "이제 우리 성도 지켜야지요. 1층을 눌러 보십쇼." | 1층 편성 창 열림 |
| place_slot | 빈 칸 → 몬스터 | "빈 자리에 부하를 세웁니다." | 배치 저장 |
| upgrade_tab | 강화 탭 | "금화로 부하를 강하게!" | 강화 창 열림 |
| upgrade_one | 첫 몬스터 강화 | — | 강화 1회 성공 |
| match_sortie | 출정 → 목록 첫 상대 | "이번엔 진짜 남의 성입니다." | 튜토리얼 공략 끝 |
| end | (말풍선만) | "이제 알아서 하십쇼, 마왕님." | 누르면 done |

- 튜토리얼 공략 상대: 튜토리얼 중 `findTargets`는 실제 플레이어를 빼고 전용 NPC 하나만 준다(`npc:tut`: 1층 슬라임 2마리, 옥좌에 약한 마왕). 1레벨 용사가 **어떤 시드로도 100% 이긴다**(테스트로 확인). 약탈은 일반 NPC 1단과 같다.
- 튜토리얼 공략이 끝나면 **서버가** `onboarding.step = 'done'`으로 바꾼다. 그래서 쉬운 NPC를 반복해서 털 수 없다.
- 강화 1회 비용(100골드)은 입문 공략 약탈(+200)로 충분하다(시작 골드 300).
- 빛낼 대상이 3초 넘게 화면에 없으면 덮개를 걷는다(게임이 멈추지 않게). 서버 호출 실패는 지금처럼 토스트, 같은 단계에서 다시 누르면 재시도.
- 기존 "층을 눌러 몬스터 배치" 힌트(localStorage `hint.floorTapped`)는 튜토리얼이 대신하므로 없앤다.

## 2. 설정

진입: 위쪽 가운데 "소리" 버튼 자리를 **설정 아이콘**으로 바꾼다(PixelLab 톱니/해골 아이콘 후보 → 승인). 아래 창(sheet)으로 열린다.

| 항목 | 동작 | 저장 위치 |
| --- | --- | --- |
| 배경음 | 켜기/끄기 + 음량 슬라이더 | 이 기기(localStorage) — 기기마다 다른 게 자연스러운 값 |
| 효과음 | 켜기/끄기 + 음량 슬라이더 | 이 기기(localStorage) |
| 닉네임 변경 | 1회 무료, 규칙은 위와 같음 | 서버 |
| 데이터 초기화 | 아래 참고, 두 번 확인 | 서버 |

- 슬라이더·토글도 CSS 색 박스가 아니라 UI 키트 그림(`bar`, `pill`)으로 만든다. 새 그림이 필요하면 후보 승인.
- 소리 값은 `services/audio.ts`가 이미 쓰는 음소거 저장을 배경음/효과음 두 개로 나눈다.

### 데이터 초기화 (되돌릴 수 없음)
- **초기화:** 성 레벨·층 배치·몬스터/함정/용사 레벨, 골드·영혼석(시작값으로), 방어 기록, 복수 기록, 이번 시즌 명예·브래킷 항목, 방치 시각.
- **유지:** 결제로 얻은 것 — 네크로맨서·새끼 용(레벨 1로), 방치 2배, 이번 시즌 패스, 남은 부활·대역·복수권. 닉네임. `processedPurchases`(중복 지급 방지 기록 — 지우면 같은 결제가 다시 지급될 수 있다). 튜토리얼은 다시 보지 않는다(`onboarding.step = 'done'` 유지, `introDone = true`).
- 골드·영혼석은 결제분과 플레이분이 섞여 있어 구분할 수 없으므로 시작값으로 되돌린다(확인 창에 적는다).
- 막는 경우: 공략 중(`run` 있음), 누가 내 성을 공략 중일 때(방어자 락). 서버가 거부하고 이유를 돌려준다.
- 확인: 버튼 → 확인 창(무엇이 지워지고 무엇이 남는지) → "초기화"를 직접 입력해야 실행.
- 서버 함수 `resetProgress(confirmText)`: `confirmText === '초기화'`가 아니면 거부. `$sender.account`만 초기화(인자로 계정을 받지 않는다). 계정 락 안에서 실행.

## 3. 서버 데이터 (Global User State `UserState`에 추가)

```ts
onboarding: {
  step: 'cutscene' | 'nickname' | 'tutorial' | 'done';
  tutorial: TutorialStep;      // 하위 단계 (위 표)
  nicknameSet: boolean;
};
profile: { nickname; createdAt; nicknameChanges: number };
```

- 새 계정: `step: 'cutscene'`, `nicknameSet: false`.
- 기존 계정(필드 없음) 읽을 때 채움: `introDone`이면 `step: 'done'`, `nicknameSet: false`(닉네임 화면만 한 번). 아니면 새 계정과 같다.
- 원격 함수(모두 `$sender.account` 기준, 인자 검증):
  - `advanceOnboarding(to)`: 정해진 순서에서 **다음 단계로만** 이동. 건너뛰어도 얻는 게 없어서 클라이언트가 불러도 안전.
  - `setNickname(name)`: 규칙·중복 검사 후 등록. 온보딩 중이면 무료, 이후엔 `nicknameChanges < 1`일 때만.
  - `resetProgress(confirmText)`: 위 규칙.
  - 튜토리얼 공략 종료는 기존 `endRaid`에서 대상이 `npc:tut`이면 `step = 'done'`.
- 호출 빈도: 단계가 바뀔 때만(한 판에 10번 안쪽). 게임 루프에서 부르지 않는다.

## 4. 클라이언트 구조

- `src/screens/Cutscene.tsx` — 컷 목록(그림·대사)을 데이터로 받아 넘기기·건너뛰기.
- `src/screens/Nickname.tsx` — 입력, 서버 오류 문구 표시(중복/글자수/금지어), 전송 중 버튼 잠금.
- `src/tutorial/steps.ts` — 단계 표를 순수 데이터 + `next(step, event)` 함수로. 테스트 대상.
- `src/tutorial/TutorialOverlay.tsx` — 어두운 덮개 + 대상(`data-tut="…"`) 주변만 뚫기 + 임프 말풍선. 누르면 `target.click()`.
- `src/screens/Settings.tsx` — 소리·닉네임·초기화.
- 플랫폼 호출은 기존 `services/api.ts`에 함수 추가(새 서비스 파일은 만들지 않는다).
- 기존 화면에는 `data-tut` 속성만 단다.

## 5. 테스트

- vitest: `tutorial/steps` 전환, 닉네임 규칙(글자수·문자·금지어), 튜토리얼 NPC 100% 승리(시드 500개), 초기화가 결제 항목·`processedPurchases`를 남기는지(순수 함수 `resetState(s)`로 분리).
- 서버 하네스: 새 계정 step=cutscene / 기존 계정 step=done·nicknameSet=false, 순서 건너뛰기 거부, 닉네임 중복 거부, 튜토리얼 중 매칭에 실제 플레이어 없음 + 튜토리얼 공략 후 done, 공략 중 초기화 거부, 확인 문구 틀리면 거부.
- 브라우저: 새 임시 계정으로 컷신→닉네임→튜토리얼 끝까지 "아무 데나 클릭"만으로 진행, 새로고침 후 다시 안 뜸, 360×640·375×667·390×844 넘침 검사.

## 6. 승인 게이트 (구현 중)

1. 컷신 그림 5장 후보 → 승인
2. 설정 아이콘·(필요하면) 슬라이더 그림 후보 → 승인
3. 튜토리얼 덮개·말풍선 스크린샷 → 승인
4. 임프 대사 전체 → 승인
